Why projects start with the duty cycle, not the schematic.

The first useful drawing of a battery system isn't electrical. It's a description of how the machine actually intends to use power — and it decides more of the final design than any datasheet does.

It's tempting to think a battery project begins with a cell. Pick the right chemistry, size the pack, wire up a BMS, done. In practice, none of those decisions mean anything until one question has an answer: what does this machine actually do with power, second by second, across a real duty cycle?

The application writes the spec

A drone pulls a short, extreme peak on takeoff and then settles into a steady, moderate draw. A warehouse robot cycles between idle, acceleration and regenerative braking dozens of times an hour. A backup power system sits at rest for months and then has to deliver everything at once, on demand. Three completely different batteries — not because the chemistry differs, but because the load profile does.

Sizing a pack around a nameplate power rating instead of the actual duty cycle is one of the most common ways a project gets more expensive later. Oversized packs cost weight and money; undersized ones fail quietly, at the exact moment the application needed the margin.

Where the number actually comes from

The duty cycle isn't guessed — it's measured or modelled from how the machine is used in the field: peak current draw, how long that peak lasts, ambient temperature range, charge behaviour, and what a safe failure mode looks like if the pack is ever pushed outside its limits. That data shapes everything downstream: cell selection, thermal design, the balancing strategy in the BMS, even the connector rating.

This is also why the same conversation happens whether the application is a piece of heavy machinery or a small mobile robot. The questions don't change — only the answers do.

The schematic comes second

Once the duty cycle is understood, the electronics follow from it rather than the other way around. A BMS built around an assumed, generic load profile can pass every bench test and still misbehave in the field, because the field never matches the assumption. A BMS built around the application's actual duty cycle is validated against the conditions it will really see.

That ordering — application first, electronics second — is a small discipline with a large effect. It's the difference between a battery that happens to work, and a system that was engineered to.
